## What it says

- A day is 16.3 million sightings (about 680,000 an hour), twice the design's
  320,000 an hour. Three days of sightings take about 7 GB, not 4.
- Loading keeps up easily: 134,000 sightings a second into the partition,
  against about 190 a second arriving.
- Closing an hour takes 4 to 9 s (median 7 s). Each count reads the whole
  day partition, because sightings have no index on seen_at; a BRIN index on
  seen_at should cut that.
- Direction's 5-minute run takes 20 to 26 s, down from about 4 minutes.
- Direction's hourly part is the problem: filling one hour's usual value
  (direction_fill_usual) takes about 4 minutes, so the run after a new hour
  takes 4.4 minutes, and the day's first run, which refills 8 hours, takes
  34 minutes. That is a query to fix when Direction moves to spy/, not a
  reason for a bigger server.
